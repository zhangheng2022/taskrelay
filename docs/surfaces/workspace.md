# TaskRelay 工作空间

Mode: Operate. Code-led implementation of the approved product plan.

The task is the stable unit: select a task, review its scope, follow execution, and answer the current challenge in one conversation. The desktop and website share this structure. RewardPilot is an architecture reference only.

First viewport: narrow persistent navigation; one sentence explaining the workspace; prominent create action; real setup states for model and device. No invented task counts or fabricated runs. Populated state uses a task list and adjacent conversation. On phones the selected task replaces the list and provides an explicit back action.

Direction contract: quiet personal workbench, warm white surfaces, dark green ink, muted green navigation, restrained amber waiting states. Chinese body text remains readable at 12–14 px; forms have named labels, focus indicators and explicit errors. Execution statuses always combine text and color.

Signature interaction: a paused task presents its exact current challenge inside its conversation, accepts a short reply, clears the sensitive field, then shows that the executor is checking the actual website. No browser takeover link.

Required states: empty, loading, offline cache, failed, unknown write, waiting for assistance, revoked device, unsupported model, narrow desktop, 390 px phone. Persist settings in their owning layer, never renderer-held credentials.
